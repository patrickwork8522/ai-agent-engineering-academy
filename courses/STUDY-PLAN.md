# Agent Atlas — Self-paced study and assessment plan

This academy is **not** a single 24-week tunnel. Choose a destination and reuse the same foundations across courses. The six first-edition guides contain 30 written lessons; exercises and capstones are the main time investment. A complete 60–90-hour engineering journey requires actually building and debugging the projects, not just reading the guide.

## Choose a path

| Goal | Core sequence | Approx. active study |
|---|---|---:|
| Understand what agents are | Foundation only | 10–14 hours |
| Identify a business opportunity | Foundation → Market & Business | 30–44 hours |
| Build useful no-code automations | Foundation → No-Code | 35–54 hours |
| Engineer agents in Python | Foundation → Engineering | 70–104 hours |
| Architect multi-agent systems | Foundation → Engineering → Multi-Agent | 105–159 hours |
| Launch a solo-founder AI product | Foundation → Business → No-Code or Engineering → Product Launch | 90–184 hours |

These totals are rough estimates. Learning speed, previous experience, API/tool setup and project scope have a large effect. For a lightweight first experience, use only the first two lessons of any specialist course and run its corresponding playground scenario.

## Repeatable study session (90 minutes)

| Minutes | Activity | Evidence to record |
|---|---|---|
| 0–10 | Predict how the concept works before reading | One-paragraph hypothesis |
| 10–35 | Read the theory and diagram | Glossary and questions |
| 35–55 | Follow a worked example or real project | Screenshot/sketch/trace |
| 55–75 | Attempt the exercise | Output or design artifact |
| 75–85 | Answer knowledge check without notes | Score and misconceptions |
| 85–90 | Explain concept in plain language | Five-sentence teach-back |

For technical project sessions, extend the hands-on portion to several hours. Stop when you can explain your results and failure cases, not when a timer rings.

## Evidence-based mastery rubric

Score each category 0–3:

- **Concepts:** 0 = cannot explain; 1 = recognizes terms; 2 = explains with examples; 3 = explains edge cases and tradeoffs.
- **Application:** 0 = no attempt; 1 = copies an example; 2 = adapts it to a new input; 3 = designs and tests an independent solution.
- **Reliability:** 0 = assumes happy path; 1 = recognizes some failure; 2 = tests failures; 3 = documents recovery, security and measurable limits.
- **Communication:** 0 = vague; 1 = repeats jargon; 2 = clearly explains result; 3 = teaches it and defends decisions with evidence.

Suggested completion gate: at least 8/12 overall with no category scored zero, plus the named capstone requirements. This is an internal learning rubric, not external certification.

## Hands-on challenge bank

Choose at least one per chapter; preserve evidence in your project journal.

1. Classify ten tasks as deterministic, LLM-assisted, agentic or human-led.
2. Write a structured extraction prompt and mark what cannot be inferred.
3. Compare an agent to a fixed workflow for a CSV exception report.
4. Step through five tool-call traces and mark permission checks.
5. Threat-model a retrieved instruction that attempts to trigger an unauthorized action.
6. Interview a user about a recent manual handover; write the process as observed.
7. Create a competitor matrix with dated sources and include manual substitutes.
8. Model light and heavy usage costs and payback sensitivity.
9. Draft an evidence-based pilot plan with go/no-go criteria.
10. Estimate a solo founder's weekly maintenance and support load.
11. Build a no-code trigger → transform → condition → review flow.
12. Compare two automation vendors on current features and exportability.
13. Extract tasks from synthetic meeting notes without inventing dates.
14. Inject five workflow failures and document recovery.
15. Produce an end-to-end no-code product prototype walkthrough.
16. Diagram the API/model/tool boundary and validate its inputs.
17. Extend the Python tool dispatcher with a constrained CSV tool.
18. Test a six-step loop against repeats, malformed outputs and timeouts.
19. Retrieve ten runbook fragments and evaluate grounding on eight questions.
20. Create a 30-case agent quality/safety benchmark.
21. Compare a router and supervisor using the same mock tasks.
22. Define structured worker contracts and task states.
23. Plan which specialist tasks can safely run in parallel.
24. Resolve conflicting agent claims using source quality and explicit uncertainty.
25. Compare a single-agent baseline to a multi-agent system across cost and quality.
26. Write a one-page MVP product contract and excluded features list.
27. Observe three target users performing a prototype task.
28. Estimate real operating costs with sensitivity analysis.
29. Design a first-ten-customers outreach experiment.
30. Write a rollback and customer communication plan for a bad release.

## Portfolio requirements

For every capstone, preserve a folder containing `README.md`, a short architecture explanation, demo evidence, test outcomes, known limits, and a retrospective. For business projects, include research sources and assumptions. For technical projects, include code, test commands, traces and a safety checklist. Never include secrets or identifiable client data without a valid basis and permission.

## Suggested assessment conversation

Use this prompt with a tutor or AI assistant after finishing a lesson:

> Act as a demanding but supportive AI agent engineering tutor. Quiz me on Lesson [ID] one question at a time, including a scenario and a failure case. Do not reveal the answer until I attempt it. Grade my explanation using concepts, application, reliability and communication (0–3 each). Identify misconceptions, give one remedial exercise, and only recommend moving ahead when I demonstrate understanding.

## Track independence

You can start Market & Business before writing any Python. You can finish the No-Code course without completing Engineering. A learner who later chooses Engineering reuses the shared foundation knowledge and focuses on the implementation depth. A learner who wants a deeper business specialization can proceed to Product Launch after either a no-code or coded prototype.
